# ADR 0002: 安全回退优先级与特权 helper 保护

## 状态

已采纳（Accepted）

## 上下文

热管理控制涉及硬件执行路径。若控制链路异常，错误下发 RPM 会带来高风险。当前产品目标是“安静、降噪、性能平衡”，必须以“先保命后追求性能”为优先。  

系统也要求菜单栏 App 与特权 helper 分离，避免 UI 进程长期持久 Root。

## 决策

1. 控制决策按以下固定优先级执行（高->低）：  
   1) 安全回退（传感器失效、helper 故障、温度异常、链路异常）  
   2) 用户手动恢复默认  
   3) 系统状态触发（睡眠唤醒、供电变化）  
   4) 应用触发（白名单进程）  
   5) 用户当前模式（静音 / 均衡 / 性能 / 自定义）
2. 一旦触发安全回退，立即停止本地控制并交还到 Apple 默认风扇策略。  
3. 所有硬件写入动作都通过受限特权 helper 进行，菜单栏 App 仅负责策略计算、状态展示与授权流程。  
4. helper 异常或未授权时，App 进入只读监控状态：保留温度/RPM 可见性，显式提示修复/安装路径。  

## 影响

- 风险边界清晰：异常条件下第一时间恢复系统默认，避免错误写值放大风险。  
- 更易审计：决策链路和回退条件可直接映射到日志和状态来源字段。  
- 用户体验可控：不会在异常状态下出现“风扇静默失败”但却无提示的状态。  
- 交付安全：helper 与 UI 的权限隔离可持续扩展，并减少后续审核与安全争议。
