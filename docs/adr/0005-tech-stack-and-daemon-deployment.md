# ADR 0005: Swift 全栈与 LaunchDaemon + XPC 部署

## 状态

已采纳（Accepted）

## 上下文

产品需要在菜单栏、CLI、后台控制与系统权限之间形成清晰边界。优先目标是可维护、可审计和权限面最小化。初期不需要多语言栈叠加，否则会加大模型共享和序列化协议成本。

## 决策

1. 主应用采用 Swift（建议 SwiftUI + XPC）实现，包括菜单栏 UI 与 CLI。  
2. 特权控制服务采用 helper，并由 LaunchDaemon 管理与恢复；与主应用通过 XPC 通信。  
3. 风扇能力探测、传感器采集与硬件写入主要放在 helper 内部实现；主应用只下发策略与展示。  
4. helper/主应用通信采用有限接口：读取状态、提交策略、执行恢复默认，不允许越权接口。  

## 影响

- 降低跨语言边界转换成本，共享领域模型和配置 schema 更容易。  
- 安全边界清晰：UI 不长期持有特权。  
- 生命周期可控：由 LaunchDaemon 负责常驻与崩溃重启。  
- 为后续签名、公证与开源审计提供一致技术栈。
